# CardFlip v1.2 acceptance test (no purchases)

## Install / checkpoint
Stop the backend; extract the archive over your working directory on a development branch. It contains source only, no .env, database, model, .git or .gitignore. No new dependencies. Keep a backup of your local database. Reload the extension in Brave and reopen its sidebar. Backend and UI should both say 1.2.0. Start Ollama if necessary. Run `.venv/bin/python -m unittest discover -s tests -q` (95 fixture/regression tests); optionally `node tests/test_capture_worker.cjs` and `node tests/test_practice.cjs` if Node is installed.

## Acceptance checklist
- [ ] Connect, check version and request budget. Scan previously cached Jordan Love, select Base/PSA 10, verify market reference and bid display. Repeat: no fresh request with a fresh cache. Check that uncertain variants and sparse sales stay labelled conditional.
- [ ] Scan a new permitted graded card, a raw card, and a numbered/auto card. Record elapsed time, exact identity/grade/variant errors, whether any bid estimate appeared, and quota consumption. Raw or ambiguous cards may only show candidate listings. Do not assume a sparse estimate is a buy signal.
- [ ] Check online reference retrieval only if needed (one extra request if uncached); confirm actual variant yourself. Check saved local reference library and optional DINO model. No new dependency if already installed.
- [ ] Open Workspace > History; verify scans/board searches are listed. Open a record; it restores identity without storing a photo, then manually request price board (may consume one request if stale). Clear History after testing: inventory and reusable caches should remain. Only latest entry per family, up to 200. Clearing history does not clear identity, reference-image or market caches.
- [ ] Select a price-board variant/grade > Log card / paper trade. Enter hypothetical purchase item price $10, shipping $2, tax $1, net estimate $20. Confirm paper entry. Paper summary should show $13 open cost, $20 net value and +$7 unrealized. Portfolio tab should not show the simulated card.
- [ ] In Paper trades record hypothetical sale: total proceeds $30, selling fees $4, shipping $3, other expense $1. Realized profit should be $9, net exit $22; ROI about 69.23%. Export paper CSV, check entries. Delete the test if desired. Do not create a real entry unless you already own the card.
- [ ] Open Player outlook > Load outlook; test Jordan Love, Cooper Flagg and a baseball player. In Career & rookie context load profile. For MLB try a prospect and Load minor-league stats. Missing or ambiguous data must remain unavailable. Check source and date. NFL injury data optional; NBA/MLB official links. No automatic live news or prospect rank feed.
- [ ] Select exact variant/grade; open Investment assessment & historical replay. Check signals; confirm identity for replay and select 7-day hold. Zero trades is valid; do not expect a profit on sparse data. Hold scenarios remain hypothetical. Replay is limited to title-derived historical sample, earlier sales for entries, later observed sale for hypothetical exit. No real execution or point-in-time player model.
- [ ] Practice at http://127.0.0.1:8765/capture-demo.html using 10–20 second rounds and user-owned/authorized photos, or use macOS screenshot-to-clipboard on permitted sources and paste into CardFlip. No direct marketplace capture or automatic bidding.

## Observation-only session
Use 10–20 cards before spending money. Note observed auction closing price, variant/grade certainty, CardFlip's conditional max, elapsed seconds, and decision (would buy / pass / uncertain). For potential entries use Paper trades, enter the observed price and estimated purchase expenses; record the source and uncertainty in Note. Only record simulated sales after a later credible comparable is observed, not from a hypothetical price projection. Measure correct identity count, usable valuations, results before deadline, API calls, and estimated margins. Paper records are not actual transactions or realized financial results. Never bid during this session.

## Limitations
Automated tests use temporary databases and fixture/mocked providers. Live Ollama, PSA, CompsAPI, sports providers, and Brave UI must be tested on the Mac. PSA paid API remains optional and not integrated. Career data and minor league availability vary; ranks are linked, not scraped. No predictive ROI/probability, multi-year training dataset or certified backtested investment strategy. Portfolio estimates are manually editable dated snapshots; no automatic refresh. History records recognized identities and successful price-board / exact lookups (not failed scans). No personal photos in history. All new features use the existing local auth and do not use CompsAPI except ordinary board or reference lookups.
